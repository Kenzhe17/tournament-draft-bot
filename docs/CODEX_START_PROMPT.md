Ты принимаешь разработку Discord-бота **r!z3** (турниры, мини-игры, экономика). Репозиторий уже содержит документацию для тебя — **сначала изучи её, не переписывай код**.

## Порядок действий

1. **Прочитай** `AGENTS.md` — жёсткие правила (не удалять данные PG, не дублировать ELO/экономику, транзакции, без секретов, без деплоя без разрешения).
2. **Прочитай** `docs/CODEX_HANDOFF.md`, затем `docs/ARCHITECTURE.md`, `docs/DATABASE.md`, `docs/FEATURES.md`, `docs/DEVELOPMENT_STATUS.md`, `docs/DEPLOYMENT.md` — в этом порядке.
3. **Осмотри код**: `bot.py` (точка входа, `setup_hook` грузит cogs), `config.py` (env и ID каналов), `utils/design/` (адаптер Components V2 — через него идёт весь UI), `storage/db.py` (схема БД), ключевые потоки в `docs/ARCHITECTURE.md`.
4. **Проверь работоспособность статически**: `python -m compileall bot.py cogs views utils storage models services games ultimatum`. Если Python недоступен — проверь синтаксис/импорты чтением кода.
5. **Убедись, что понимаешь**, почему нельзя менять рабочие системы без изучения зависимостей: ELO/монеты начисляются в `kd_input_view.process_match_result` один раз (флаги `processed_elo_matches`/`processed_match_ids`); UI рендерится только через `utils/design.compose`; JSON-сторы в `DATA_DIR` дублируют/дополняют PG.

## Известные проблемы (из handoff)

- Секреты в истории git (токен в `.env.example`, webhook в `config.py`) — нужна ротация, не трогай прод.
- Нет автотестов; `test_*.py` в корне — ручные скрипты.
- Magic ID каналов захардкожены — при добавлении фич не плоди новые литералы, используй `config.py`.
- Временная диагностика `-# view=…` в `/tournament create` — кандидат на удаление.

## Как определить следующую задачу

Спроси меня, что делать, или выбери из `docs/DEVELOPMENT_STATUS.md` (приоритеты: ротация секретов → параметризация ID → Team Preview → тесты). **Не начинай рефакторинг и не меняй игровую логику без моего подтверждения.** Перед любым изменением опиши план и затронутые модули.
