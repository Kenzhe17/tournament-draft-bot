# r!z3 — Живой Discord E2E на Railway Test

Процедура проверки Mixed OCR (коммит `ab64efd` + aux_review/гейты).
**Production не деплоить.** Выполнять только на тестовом боте/сервере.

## Предусловия

- [ ] Railway Test-окружение запущено, бот онлайн (`/ocr` отвечает).
- [ ] Тестовый сервер с 2 командами × 4 игрока, у всех привязаны Discord-аккаунты.
- [ ] Доступен Discord server administrator (аккаунт с правом Manage Server).
- [ ] Модель OCR прогрета/закэширована (нет download при старте — проверить логи).

## Подготовка данных

- [ ] Скриншот **полного CS 4×4** результата матча.
- [ ] Скриншот **скриншота отряда** (squad) для комнаты 1 — желательно с
      намеренным расхождением одного значения (например DMG игрока A1:
      Classic=2500, Squad=3200) для проверки конфликта.
- [ ] Скриншот отряда с **неоднозначным/лишним** игроком для проверки
      `aux_review` (или оставить как есть, если aux_review не возникнет —
      шаг 6 тогда пометить N/A).

## Сценарий

### 1. Две комнаты, смешанная загрузка
- [ ] Начать турнир/матч с 2 комнатами (4×4).
- [ ] Комната 1: загрузить **один полный скриншот + один скриншот отряда**
      в одном сообщении/комплекте (порядок файлов любой).
- [ ] Комната 2: загрузить полный скриншот (classic) или 2 squad-скриншота.
- [ ] Проверить: сообщения комнат опубликованы с кнопками; прогресс
      «Комнат: 2/2».
- [ ] Проверить: в комнате 1 предупреждение о конфликте/расхождении
      отображается; в комнате 2 — нет.

### 2. Маппинг 8 игроков
- [ ] Привязать всех 8 OCR-игроков к Discord ID через UI маппинга.
- [ ] Убедиться: агрегация суммирует K/D/A/DMG по комнатам по Discord ID
      (не по нику). В сообщении подтверждения проверить суммы вручную.

### 3. Конфликт и выбор Squad
- [ ] Открыть сообщение «ПОДТВЕРЖДЕНИЕ РЕЗУЛЬТАТОВ» → кнопка
      «⚠️ Конфликты (N)».
- [ ] **От обычного игрока** нажать «Конфликты» → ожидается отказ
      «❌ Нет прав» (эфемерно).
- [ ] **Server admin** открывает «Конфликты» → для конфликта DMG A1
      выбрать **Squad (3200)**.
- [ ] Проверить: в сообщении подтверждения предупреждение уменьшилось
      (N уменьшился), после последнего конфликта — предупреждение и
      кнопка «Конфликты» исчезли (сообщение обновлено без переотправки).
- [ ] В агрегированной статистике A1 DMG = squad-значение (3200) за эту
      комнату + вклад второй комнаты.

### 4. aux_review
- [ ] Если в комнате 1 есть `aux_review` — кнопка «🗑 Игнорировать
      доп. данные (N)» видна только администратору; обычному игроку —
      отказ.
- [ ] Admin → «Подтвердить игнорирование» → блокировка снята,
      предупреждение исчезло из confirm-сообщения.
- [ ] Повторное нажатие / второй админ → «уже подтверждены», без дублей.
- [ ] Проверить в данных (логи/отладка): `aux_review_confirmed.by` =
      Discord ID админа, `at` = ISO-время.

### 5. Финализация и ELO
- [ ] Admin жмёт «✅ Подтвердить результаты» → финализация.
- [ ] Проверить: ровно **одно** начисление ELO каждому игроку
      (рейтинги/история — один delta на матч).
- [ ] Повторно нажать «Подтвердить» / вызвать финализацию повторно →
      идемпотентно, **без повторного ELO**.

### 6. Откат и SHA-recovery
- [ ] «Исправить статистику» / откат комнаты → связанные
      `stat_conflicts` и `aux_review` комнаты очищаются; состояние
      блокировки пересчитывается корректно.
- [ ] Переопубликация интерфейса комнаты после рестарта/потери сообщения
      → SHA-256 проверяется, **OCR не запускается повторно** (в логах
      нет повторного `process_room_bundle` для того же комплекта).
- [ ] Повторная загрузка того же комплекта (дубликат) → не создаёт
      вторую комнату, не дублирует статистику.

### 7. Параллельность (по возможности)
- [ ] Два админа одновременно жмут «Конфликты»/выбирают источник —
      один получает «ok», второй «уже resolved», значение не смешивается.
- [ ] Два админа одновременно подтверждают aux_review — одна запись,
      второй «уже подтверждены».

## Нельзя проверить без Railway Test / живого сервера

- Реальные тайминги OCR на Railway (p50/p95), потребление памяти/RSS.
- Поведение под реальной нагрузкой Discord API (rate limits, retries).
- Живые E2E-сценарии выше — **не выполнялись** на момент коммита.

## Критерии готовности к Production

- [ ] Все пункты сценария 1–6 пройдены на Railway Test.
- [ ] Пункт 7 — желательно; минимум — unit-тесты гонок зелёные.
- [ ] Нет повторного ELO ни в одном сценарии.
- [ ] Production deploy — только после явного подтверждения.
