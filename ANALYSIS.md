# Анализ проблем текущей системы

## Критические проблемы

### 1. Двойное хранилище (JSON + PostgreSQL)
**Проблема:**
- Два хранилища параллельно: `json_store.py` и PostgreSQL
- Риск рассинхронизации данных
- Усложнение отладки
- Непоследовательное поведение

**Решение:**
- Убрать JSON store полностью
- Использовать только PostgreSQL
- Мигрировать все данные в PostgreSQL

### 2. Сложная модель Tournament
**Проблема:**
- Слишком много полей (50+) в одной модели
- Временное состояние смешано с постоянным (temp_match_stats, pending_winners)
- Сложная логика с множеством условий
- Трудно поддерживать и тестировать

**Решение:**
- Разделить на отдельные модели: Tournament, Match, Team, Player
- Отдельная таблица для временного состояния
- Четкое разделение concerns

### 3. Дублирование кода в views
**Проблема:**
- Одинаковая логика в `matches_view.py`, `final_view.py`, `match_stats_view.py`
- Повторяющиеся паттерны для работы с командами
- Много boilerplate кода

**Решение:**
- Объединить все tournament views в один файл
- Создать базовые классы для общих паттернов
- Вынести общую логику в utils

### 4. Отсутствие Service Layer
**Проблема:**
- Бизнес-логика распределена по views
- UI логика смешана с бизнес логикой
- Сложно тестировать бизнес логику отдельно

**Решение:**
- Создать services/ с бизнес логикой
- Views только для UI
- Четкое разделение concerns

## Средние проблемы

### 5. Сложная логика подтверждения победителей
**Проблема:**
- Много async методов с похожей логикой
- Дублирование кода сохранения статистики
- Сложно отследить выполнение

**Решение:**
- Упростить до единого метода confirm_winner()
- Вынести логику сохранения в отдельный сервис
- Убрать дублирование

### 6. Проблемы с async/await
**Проблема:**
- Смешение sync и async методов
- Не все методы правильно помечены async
- Сложно отслеживать await вызовы

**Решение:**
- Четко разделить sync и async
- Все операции с БД - async
- Все Discord interactions - async

### 7. Временные файлы в production
**Проблема:**
- test_*.py файлы в корне
- debug_output/, calibration_output/ директории
- Мусор в репозитории

**Решение:**
- Переместить тесты в tests/
- Удалить отладочные файлы
- Добавить .gitignore для временных файлов

## Низкие проблемы

### 8. Сложная структура директорий
**Проблема:**
- Слишком много уровней вложенности

**Решение:**
- Упростить структуру

### 9. Отсутствие документации
**Проблема:**
- Нет README для разработчиков
- Нет документации API
- Сложно понять архитектуру

**Решение:**
- Добавить документацию

- Добавить примеры использования

### 10. Слабое логирование
**Проблема:**
- Мало структурированного логирования
- Сложно отследить ошибки
- Нет метрик

**Решение:**

- Добавить метрики
